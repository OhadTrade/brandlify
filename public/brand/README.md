# Brand assets

Everything in this folder is **generated** from the owner's source artwork in
`assets/source/` by `npm run brand`. Edit the sources, not these files.

| File | Use |
| --- | --- |
| `lockup-horizontal.png` | Original artwork — light backgrounds only |
| `lockup-horizontal-ondark.png` | **Navbar.** Wordmark tone-mapped for `--color-base` |
| `lockup-stacked.png` | Recomposed stacked lockup — light backgrounds only |
| `lockup-stacked-ondark.png` | **Footer / interior pages** |
| `lockup-stacked-original.png` | The owner's stacked render, kept for reference (unused) |
| `mark.png` | Icons, small placements |
| `mark-1024w.png` | Hero fallback (mobile / reduced-motion / no WebGL) |
| `mark-white.png` | Monochrome placements |
| `wordmark.png` / `wordmark-ondark.png` | Wordmark on its own |
| `og-image-1200x630.png` | Default Open Graph card |

App icons (`/public/icon-*.png`, `apple-touch-icon.png`, `icon-maskable-512.png`,
`favicon.ico`) are generated by the same script onto the `#08060E` canvas.

## Two known limits in the source artwork

**1. The lockups are built for a light background.** The wordmark's median
colour is `#280C66` — **1.28:1** against `--color-base` (`#08060E`), i.e.
invisible. The `-ondark` variants remap the wordmark's luminance onto a
light-violet metallic ramp (median **6.94:1**) while leaving the mark's magenta
untouched. Letterforms and bevels are preserved exactly; only the tone changes.
*Preferred fix: the owner supplies official dark-background lockups, which drop
straight into `assets/source/` and make the tone mapping unnecessary.*

**2. The supplied stacked render is much softer than the horizontal one.** Its
wordmark extrusion is partly melted and reads badly at any size. The stacked
lockup shipped here is therefore laid out from the *same pieces* as the crisp
horizontal file — identical mark, identical letterforms, only re-arranged
(`composeStacked()`). The owner's original is kept as
`lockup-stacked-original.png` for comparison.

**3. The mark's usable resolution is 318×412.** `mark-1024w.png` is an upscale
of that. It holds up behind the hero glow, but a higher-resolution render (or an
SVG) of the mark would be better — and would also let the favicons be crisper.

The 3D hero `B` is **not** any of these PNGs: it is geometry built in Three.js
from the mark's 45° triangle grid (stage 5).

## The 3D render — `assets/source/mark-3d.png`

A clean, high-resolution render of the mark, supplied by the owner. It is not
shipped to the browser; it is the **measurement source** for the geometry.
`scripts/measure-mark.mjs` reads it and produces both halves of
`src/components/hero/markGeometry.ts`:

- the **cell map**, by probing the alpha channel at each candidate triangle's
  centroid on a landmark-anchored 3×4 grid;
- the **per-facet colours**, as the median and the 12th/90th luminance
  percentiles of the pixels inside each front face.

This replaced `extract-triangles.mjs` + `sample-facet-colours.mjs`, which both
read `mark.png` — and that file is where a real bug came from. At 318×412 with
soft edges, the B's two **counters** (the holes that make it a B rather than a
filled block) are muddied shut, so the extractor faithfully reported a solid
grid and the hero rendered a solid block for months. The new measurement finds
them: `(1,1)` is `LR` and `(2,1)` is `UR`, and note that `(1,1)` runs on the
*other* diagonal — that is what shapes the upper counter.

Everything driven by that geometry now has the counters: the WebGL hero, the
static hero fallback, the favicons, and the teaser films.

**Still outstanding:** `mark.png`, `mark-1024w.png` and the lockups are cut out
of `assets/source/lockup-horizontal-src.png`, which is the old artwork — so the
navbar and footer logo still show the solid B. Rebuilding the mark half of the
lockups from `mark-3d.png` would close that gap.
